# 仪容仪表 AI 影子检查 V1

开发分支：`feat/ai-evidence-review-20260925`。初始基线：`abb6019`。
功能方案及三端效果图均已确认后开始开发。2026-09-25 用户批准合并、推送、部署；发布证据另行记录，不能将发布许可等同于已上线。

## 本期入口与闭环

1. 管理员：配置中心 → 岗位工作模板（工作包中心）→ **AI 检查规则**。
   选择岗位、门店、原工作项；填写制服、工牌、规定装备规范及合理例外，上传合格/不合格样例。
   保存产生新版本；启用的是影子规则，并非正式自动审核。草稿不覆盖当前启用版本。
2. 员工/原工作提交人：角色工作台 → 我的工作 → 已提交的原工作 → **仪容仪表 · AI 检查**。
   一人一组证据，通过账号任职手动关联人员；不是人脸识别。
   从原工作选图或上传补充照片后提交检查。模型配置齐备时，后台队列自动执行视觉观察。
   无模型、失败、限额、证据失效均明确展示并允许人工复核，绝不伪装成通过。
3. 主管：角色工作台 → 团队工作 → **仪容仪表复核**。
   按当前任职和授权门店查看待复核记录，对照受保护的原图及观察位置，填写理由后要求补拍、确认符合或撤销误判；查看处理历史。

已有主任务提交不直接把所有附件发给模型。晨会任务可能同时包含合照、会议记录和多名员工，必须先明确检查人员及对应照片；之后的模型处理自动执行。
管理人员代选员工的记录仍由原提交人补拍/申请复核；本期未开放员工直接查看或修改他人负责的整项晨会记录。需要员工各自发起申诉时，使用本人负责的工作记录。

## 正式业务边界

- 仅制服、工牌、规定装备三个客观项目；不启用妆容自动判断，也不推断身份、性别、态度或性格。
- 模型结论及本面板人工结论均是**影子记录**。不改 `work_record`、工作期望、日报、库存、KPI 或工资状态。
- 正式工作复核仍在原有工作详情操作；不能把影子“确认通过”当成正式工作审批。
- 同一工作、同一员工只建一条检查链。原证据与补拍按版本关联；相同请求幂等，重复旧照片不重复计费。
- 已审核锁定的主工作也能上传影子补充照片，照片单独存储，不追加或改写锁定的正式证据。
- 原提交人和被检查人均不得自我复核。表单按钮不是授权依据，所有接口再次核验权限。
- 不确定结果为“无法确认”，不会自动算违规。失败不改变原提交时间，不会因 AI 排队而给员工判逾期。
- 自动通过、自动退回、企微整改催办和绩效扣减**未启用**，须另行验收确认；不承诺减少多少人工审核或识别准确率。

## 权限、图片与模型

- 管理端仅 PLATFORM_ADMIN / GROUP_ADMIN；普通经营高管没有规则写权限。
- 查询和处理复用当前工作可见范围，限制租户、门店、任职及上下级范围。部门记录归并到所在门店。
- 原图和样例通过鉴权接口读取，不产生长期公开链接；管理员样例不开放给员工下载。
- 本期每次最多 4 张 JPG/PNG、单张不超过 5 MB，最多 6 张规范样例。通过现有安全扫描后才能使用。
- 模型用图在内存中缩至最长边 1024 像素，原件不变；不上传员工姓名、手机号、账号或可访问的图片链接。
- 员工工作照片及补充检查照片沿用普通照片 5 天策略；规范样例按用户 2026-09-25 的明确要求长期保留，不到期、不自动清理，也不允许通过通用文件删除入口删除。上线前须核实图片清理任务启用状态。
- 新旧样例均依据图片台账的 `ai_evidence_sample` 类型免于过期，不需要重新上传或刷新上传时间。“移除关联”只从新规则版本中取消引用，原样例和历史版本不删除。已物理删除或缺失的照片不会被虚假恢复；争议工作图片仍遵循原有重要证据保留规则，不因样例策略被延长。
- 补充照片记录服务端接收时间；浏览器声称 CAMERA 不构成真实拍摄时间、人员身份或防作弊证明。
- 检查结果与事件保留结构化事实、规则版本、证据编号/摘要、处理理由、操作者、时间、Token 用量，不保存 Base64 或模型原始响应。
- AI 审核日志的最终保留期限、争议证据期限和复核时限尚待业务确认，本次不执行历史数据清理。

## 安全关闭与后续接通

后端提供百炼 Qwen 和 DeepSeek 官方视觉接口适配器，但以下条件必须同时具备才会外发照片。选择服务商不会自动启用队列或外发：

| 环境项 | 默认 | 说明 |
| --- | --- | --- |
| AI_EVIDENCE_ENABLED | false | 队列处理总开关 |
| AI_EVIDENCE_EXTERNAL_APPROVED | false | 经确认的数据外发开关 |
| AI_EVIDENCE_PROVIDER | qwen | 可选 qwen / deepseek；保留原默认值，不暗中切换服务商 |
| AI_EVIDENCE_API_KEY | 空 | 仅后端受控密钥，不进前端/仓库 |
| AI_EVIDENCE_TENANT_IDS | 空 | 显式租户名单；启用总开关却未配置会拒绝启动 |
| AI_EVIDENCE_PILOT_HOTEL_IDS | 空 | 生产必须配置批准的门店清单；配置、提交和模型取图均再次限制，不影响历史记录查阅 |
| AI_EVIDENCE_MODEL | 随服务商 | 空值时 qwen 使用 qwen3-vl-plus，deepseek 使用 deepseek-flash |
| AI_EVIDENCE_ENDPOINT | 随服务商 | 空值时使用对应服务商官方接口；显式地址也必须匹配该服务商 HTTPS 白名单 |
| AI_EVIDENCE_DAILY_REQUEST_LIMIT | 100 | 单租户北京时间自然日调用上限，包括重试 |

每天次数上限不是费用上限。输入/输出 Token 仅记录服务端获得的用量，网络失败时仍可能计费，须与供应商账单核对。
调用在专用调度线程上执行，网络请求不占用数据库事务；45 秒总等待、128 KB 响应上限、三分钟工作租约。
失效任职、超过限额及已被补拍替代的排队任务不会发送图片；中断任务进入显式失败状态，最多允许 3 次尝试。
人工给出的角色、照片文字和模型 JSON 都不能直接调用绩效、库存或权限操作。

模型适配参照官方接口：

### DeepSeek 官方接通准备（2026-09-25）

用户已确认使用 DeepSeek 官方平台。当前官方[视觉接口](https://api-docs.deepseek.com/zh-cn/guides/vision/)支持 `deepseek-flash` 图片输入；[JSON 输出](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)和[思考开关](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)使用该服务商的参数格式。

- 显式配置 `AI_EVIDENCE_PROVIDER=deepseek`、`AI_EVIDENCE_MODEL=deepseek-flash`，端点为 `https://api.deepseek.com/chat/completions`（也接受官方 `/v1/chat/completions`）。旧百炼端点未清除时拒绝启动，不跨服务商兜底。
- 只发送内联图片，不调用 Files API、不建立外部长期图片副本、不发图片公开地址。使用 `thinking.type=disabled`、JSON 输出和 1200 输出 Token 上限；保留原有时限、图片限制及人工复核边界。
- 空内容、非 JSON、截断结果、非 200 响应均按失败处理；异常不带上游返回正文、密钥或图片。无自动重试和服务商切换。
- 官方密钥与第三方转售接口不可混用；本适配不接受任意代理域名。未核验模型实际能力前，不承诺制服/工牌识别准确率。
- 本机密钥录入可双击 `tools/ai-evidence/01-Save-DeepSeek-Key.cmd`。输入不可见，使用 Windows 当前用户加密保存到 `%LOCALAPPDATA%/Sifangguan/AI/credentials/deepseek-api-key.clixml`；不保存明文、不输出密钥、不进入 Git，不自动上传或调用模型。之后只报告“密钥已保存”。该加密文件仅供当前 Windows 账号使用，不能直接复制到 Linux 服务器使用。
- 已有密钥不会无提示覆盖；需要更新时显式运行 `Set-DeepSeekCredential.ps1 -Replace`。实际上线时通过受控 SSH 输入在后端配置，绝不把密钥写入前端、命令行参数、构建包或日志。

先做一次非员工合成图的实际调用，核对账号授权、图片输入、结果格式和真实 Token，再决定门店试点范围及限额。适配单元测试仅是离线验证；真实调用验收另见下节，不能将其等同于线上已启用。
