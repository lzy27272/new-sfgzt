# AI 中台统一分析入口

## 本次范围

入口：经营中心 → AI 数据与复盘，页面 `/#/ai-data`。

两个业务项目仍独立运行；新增入口不搬迁业务数据库，也不把离线备份电脑当作分析数据库。

| 数据集 | 来源与边界 |
| --- | --- |
| WORK_RECORDS | 中台工作执行结构化状态，复用工作可见性策略 |
| DAILY_REPORTS | 中台日报提交/审核状态，复用日报可见性策略，不含正文 |
| TASKS | 中台已有任务服务授权后的状态；上游最近 500 条限制会明确提示 |
| KPI_FACTS | 授权组织/任职的结构化绩效事实，排除 PAYROLL_SENSITIVE |
| OTA_DAILY | 显式绑定门店的每日最新修订事实，源保留 2 年 |
| OTA_HOURLY | 显式绑定门店的小时累计快照，源保留 48 个月；不能按小时相加 |
| OTA_PERIODS | 月/季/半年/年度汇总，源保留 5 年；不同 period_type 不能混加 |

留存期限不等于已有历史覆盖。首次抓取以前的数据、缺失日期、未完结期间不能补零或冒充完整同比。原始报文、员工联系方式、薪资、附件、日报自由文本和工作计划未开放。

## 接入与权限

服务器地址为 `https://www.sfgzt.cn/api/v1/ai-data/mcp`，提供无会话的 Streamable HTTP JSON 响应。

在页面按设备创建独立密钥，默认只读，最长 30 天，保存报告须单独勾选。密钥只在创建时显示，数据库只存 SHA-256。新设备须自行完成配置与授权，不会随 Codex 登录自动开通。

```toml
[mcp_servers.sifangguan]
url = "https://www.sfgzt.cn/api/v1/ai-data/mcp"
bearer_token_env_var = "SFG_AI_DATA_TOKEN"
```

把密钥保存在该设备安全环境配置中，不要提交到仓库、聊天、报告或截图。

每次请求重查账号、任职和当前权限，过期/撤销/禁用账号立即拒绝。连接密钥不能调用普通业务写接口。页面入口的 `ui.module.ai-data` 默认仅授予现有平台管理员与 CEO 账号角色；其他岗位通过原有岗位草稿发布流程授权。菜单授权不增加底层业务读权限。

工具：`data_catalog`、`query_data`、`list_reports`、`read_report`；写授权连接另有 `save_report`。没有任意 SQL、改价、改库存或修改绩效工具。

## 报告与快照

取数每页 500 条，使用返回的 nextOffset 继续；先读完需要的分页再分析。快照临时可引用 30 天，下一次同账号取数会清理已过期临时快照。每日每账号最多创建 1,000 个快照。

保存报告必须引用本人当前权限范围内尚未过期的快照，最多 8 份。至少一份快照期间与报告周期一致；可另附真实的环比、同比期间快照。报告内独立保存证据和散列，不随源数据或临时快照变化。

同一 requestId 重试幂等；改正文需新 requestId，旧报告不可覆盖。报告是待人工核验的草稿，不自动改变业务事实。报告仅本人且仍保留来源权限时可读；权限指纹变化后旧报告会暂不可读，需要重新取数保存报告。

## 部署边界

V68 为仅新增对象的完整迁移，按 FULL 发布：加密备份、实际恢复演练、隔离数据库迁移检查、安装、迁移、健康检查与最终发布审计。保留前一版本用于应用回退，不删除旧业务表。

门店映射必须用已验证的来源租户/门店和中台组织建立，不得按相似店名批量匹配。映射不能重新指向别的租户/门店；需要变更时停用旧映射，建立新映射。

跨来源只读函数由迁移所有者执行；需要给该所有者授权 `ota_analytics` schema USAGE，以及 hourly_operating_fact、daily_operating_fact、period_rollup 三表 SELECT。不应给应用登录角色直接查询所有源数据的权限。

## 尚未启用的功能

无人值守的周/月/年 AI 执行器和定时任务尚未配置。需要独立 AI 服务授权、网络连通、执行身份与排程验收后才能启用。不能复制用户桌面 Codex 登录凭据至服务器，也不能用普通汇总脚本冒充 AI 复盘。当前状态为 EXECUTOR_NOT_CONFIGURED，已授权的设备可主动取数分析并回存。
