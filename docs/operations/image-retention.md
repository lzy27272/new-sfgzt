# 工作图片自动清理

## 生效规则

- 普通图片从服务端确认上传成功起保留31×24小时。未审核不延长保存期。
- 重要证据由全租户范围的平台/集团管理员在“配置中心 → 数据留存策略 → 图片保留与重要证据”标记，并填写原因。解除保留也记录原因；已经到期的图片解除后进入清理。
- 到期立即停止业务下载，后台默认每5分钟检查一次，每轮至多200个对象。失败对象30分钟后重试。
- 只删除图片文件，保留工作记录、任务、日报、指标、报告和附件元数据。PDF、Word、Excel和经营数据不在本执行器清理范围。
- 同一个文件在工作记录和多个日报中的引用共享一个计时与保留标记，不因审核、复审、生成日报或复制引用重新计时。

## 执行开关与验收

三个条件同时满足才会运行：部署环境 `DATA_RETENTION_CLEANUP_WORKER_ENABLED=true`、显式配置 `DATA_RETENTION_TENANT_IDS`、租户策略 `image_cleanup_enabled=true`。部署前先保持关闭，完成数据库备份恢复演练、对象盘点和候选预览，再将该租户图片期限改成31天并开启；其他策略字段必须保留原值。

后台唯一删除入口按对象逐个检查租户、期限、重要证据标记、受管目录、无符号链接、文件大小和SHA-256。只删除明确的单个文件，不遍历清空目录。租户开关共享锁与对象行锁避免与关闭/标记保留操作竞争。文件删除与数据库无法组成同一个原子事务，重试时“文件已不存在”可补记清理结果；保留接口拒绝对已经缺失的文件声称保留成功。

查看日志中的 `Image retention scan`，确认任务真实执行而非仅配置开启。`IMAGE_RETENTION_DELETED` 审计与 `image_retention_object` 永久保留清理元数据；失败代码不泄露文件内容。数据库启用并强制租户行级隔离。升级SQL只登记元数据，不删除文件或默认开启执行器。

## 存储边界

当前执行器覆盖服务器受管附件目录中的工作图片、任务图片，以及引用同一文件的日报图片。`image_retention_object` 是生命周期权威台账，旧 `attachment` 留存字段仅为兼容元数据。

当前异机拉取链路主要保存数据库/盯盘加密备份，尚未接入业务图片文件备份。不能将本功能的上线描述为“异机图片备份及其自动清理已完成”。今后接入对象存储、图片备份、缩略图或版本副本，必须使用同一上传时间、保留标记和删除台账；未做到前不能承诺全副本31天物理清除。离线设备也无法立即物理删除，需上线后补清理并确认。

恢复旧数据库不能恢复已经到期删除的图片。不得从长期归档重新导入过期图片文件；后续图片副本恢复流程需重放删除台账。员工自行下载或转发的副本不在服务端清理范围。

## 回退

先关闭部署开关或租户图片清理开关。回退代码前保留新增台账与迁移记录，不回滚业务数据库。已经物理删除的图片不可通过关闭开关恢复。开启前须确认重要证据已标记，并核对候选清单。
