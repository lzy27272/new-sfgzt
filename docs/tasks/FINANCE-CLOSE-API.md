# F20 真实来源月结与净额银行核对

V99 提供服务端 `FinanceCloseV2.extraChecks(jdbc, principal, book, month)`，原月结规则在全部旧检查之后合并新增检查；不接受客户端上送“全部完成”代替业务事实。

API 前缀 `/api/v1/finance/close`。

| 接口 | 行为 |
|---|---|
| `GET /context?bookId=&month=YYYY-MM` | 授权账套、固定来源清单、实时实际控制数、真实银行净分配与独立说明状态 |
| `POST /registers` | 本账套本月逐项列明全部来源适用/不适用、原件依据及控制数；不会自动确认 |
| `POST /registers/{id}/review` | 后台配置财务总监独立复核，来源经办人不能自审，审批后原件变化使原核对失效 |
| `POST /bank-explanations` | 逐笔银行差异说明，冻结原流水、净分配及逆向明细，不能说明超分配 |
| `POST /bank-explanations/{id}/review` | 配置审核人独立确认；以后同额撤配/重配也会使旧快照失效 |

固定来源：员工报销、采购验收、实际领用/盘点、资产、PMS、OTA、客户、渠道、银行、工资、租赁/待摊、税务、内部往来、未清期初债项。每项都要明确适用或不适用；确有本期事实时不能选择不适用，后续新事实会再次阻止关账。

门禁直接核对：已验收但未确认采购、未捕获或未过账存货、应提未提资产、未确认收入/工资、未过账业务事件、遗漏的月度计提、待复核版本、真实现金净匹配、银行账户法人、有效原件、安全状态/哈希、税务申报/缴款回执及应付总账确认。V104 后的未完成真实成本维度问题也必须列明，不以零实际掩盖。

银行净额统一使用实际会计日期截止的 FX（报销/旧 FO）与 FB（收入/工资/期初/内部）函数，再叠加 FS 实际退款分配。撤回是追加逆向事实，不删除原分配。收入核销 `REDEEM` 不代表现金，因此不会当作银行实收。银行缺法人或超额匹配不能通过手写解释放行。

附件原件字节存在性和下载哈希仍由原件服务验证。月结检查校验数据库原件凭据、原票状态、安全结果与实际回执关联，不声称已逐个检查磁盘文件。

验证：`FinanceCloseV2IntegrationTest` 在真实 Embedded PostgreSQL、非超级用户 app 角色及强制 RLS 下覆盖七项场景。旧 V99 七项已通过，V104 成本维度新增集成仍需根任务统一全量验收。此文不代表生产部署完成。
