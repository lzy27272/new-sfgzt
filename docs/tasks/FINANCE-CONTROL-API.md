# 财务 V2 控制、资金及当前待办

本文件描述本轮源码接口，不作为生产已上线或实际转账证明。所有接口使用真实请求身份、租户RLS、组织范围及来源权限。工资和税务仍需独立敏感权限。

## 当前节点和企微

`GET /api/v1/finance/todos?page=&kind=`：50项统一分页，`kind`可为review/payment/returned/receipt/work。类别统计与列表来自同一授权集合，不先截取各模块第一页再拼总数。有效跨日事项保留；返回真实来源及`target`，岗位工作台复用同源数据，不把财务待办算作日常工作完成率。

包括报销/实际业务、资金指令、计提修订和实际调度异常、收入/工资/双边往来、凭证/科目发布、分析报告及建议跟进、差错更正、应收差异/恢复、税历、预算例外、代理发布、关账核对、档案申请和误选发票释放。盘盈估值、进项原票拆税、应纳计提、净未付工资和税款、尚未归档的有效税务义务、已发放且真实净未清的逾期借款也接入同一队列。无当前处理权的人不会因拥有菜单而取得待办；税务整法人快照按冻结全部组织范围核权，不把单店授权扩展为全法人可读。

`app.finance-reminders.enabled`默认关闭；启用必须明确`app.finance-reminders.tenant-ids`白名单。默认Asia/Shanghai每日9:00和15:00，可配置cron。按真实账号/有效任职解析身份，逐页取同一待办；日/账号/来源/节点/版本幂等。只发个人企微，不发群，不带金额或原件。企微绑定缺失明确保留站内状态，不称作已送达。

发送前再次通过`FinanceDeliveryEligibilityService`解析真实有效身份、组织及独立敏感权限，并核对同来源仍是本人的当前待办。撤权或事项已处理时，V108将投递记为`SUPPRESSED`，保留原因/时间，不写SENT或伪造发送ID，不继续指数重试。网络故障仍按原FAILED重试处理。站内通知和企微深链均保留独立服务端授权。

## 资金指令 `/api/v1/finance/control`

- `GET /context|/cash-sources|/cash|/cash/{id}`：当前范围内真实已批来源、资金指令及冻结账户；`sourceCurrent=false`的未执行旧指令明确提示作废重建。
- `POST /cash`：真实CLAIM/OPERATION、原版本、金额/日期、实际同门店同法人的银行账户及收款对象。付款必须有真实收款账户；冻结账户和受益人版本，不用文字摘要代替。
- `POST /cash/{id}/review|reject`：冻结的独立资金复核人；申请人、制单人及出纳不能代为自审。
- `POST /cash/{id}/void`：仅冻结参与人且仍具当前review/pay、范围及敏感权限，可明确作废DRAFT/APPROVED。旧制单人只获得该指令的读取/作废权，不因此取得原整张单据读取或执行权。EXECUTED不可作废，须独立差错更正。
- `POST /cash-batches`：仅冻结出纳登记已实际发生资金。来源、审批版本、银行/受益人资料、合同节点、净已付、净应付、借款借款人有效状态等重新核对。整批原子且幂等，不发起银行转账。付款登记、银行匹配、回单归档及会计过账是不同事实。

## 策略、合同、差旅与借款

- `GET/POST /policies`，`POST /policies/{id}/publish|retire`：CATEGORY/WORKFLOW/BUDGET/TRAVEL/ENTITY/CASH_PLAN/RETENTION；独立发布，冻结版本，不硬编码人名或金额档位。类别预算必须显式真实类别ID/稳定编码，不从UUID、名称推测。
- 预算区分门店/部门/真实项目、费用/资本/库存资金；费用只使用真实消耗或当期分摊，不把付款及购入库存当费用。库存资金的累计已确认购入基数仍占资金限额，不因验收释放承诺而可重复申请。源事实桥接、修订和跨期不重复占额。
- 无明细报销在财务复核中调整核准金额、类别或处理方式时，按最终核准事实在同一审核事务重新校验预算；超出 BLOCK 限额则审核及占用一并回滚。允许的调整释放原分类占用，后续终审不复活已释放记录；原申请金额保留，不用核准额覆盖。没有调整的审批保留原预算快照，多明细单仍须退回逐行修改。
- 特定项目预算遇同期间/类别/部门的历史未核项目占用，提示待核而非过滤为零。显式确认的NONE不冒充某个项目。不能直接改已冻结历史；可核实后使用独立总预算或下一期项目预算。
- `GET /contracts/{id}`、`POST /contracts/{id}/revisions`、`POST /contract-revisions/{id}/review`：真实合同付款计划/质保金及独立变更。不得删掉已发生付款的节点或降低到净已付之下；资金更正及核销保留原来源。
- `GET/PUT /travel/{claimId}`：本人当前可编辑草稿及版本、实际同行人和已发布标准。只能选同店真实在职账号，不接受任意UUID。页面每次修改即账号/任职隔离加密暂存；切出重进可恢复，明确保存才进入云端，旧云端版本冲突不静默覆盖。
- `GET /loans/{id}/clear-candidates`、`POST /loans/{id}/clear-claims`：同借款人/实际法人/组织、已批费用报销、实际已发未还净借款和报销未付额的部分冲抵。原借款核销及报销抵款同时留不可变事实，不产生第二次现金付款。工资、资本报销和他人单据不能混抵。
- `GET /loans/exit-check`及员工真实离职/删除流程共用借款守卫；任职切换不等于离职。未实发的批准借款额度不假装个人已欠款，但实际出借时再次检查员工状态。

## 限时代理

授权入口见`/api/v1/finance/authorizations`。发布需要另一名配置人，代理人必须已具备实际审核权限及组织范围，授权本身不授权。审批路线保留原责任人；冻结各个不重叠的有效时间窗，原人自审回避不因代理而绕过。仅当前有效窗口的代理可办，未来代理不能提前办理；过期/撤销恢复原责任人，原快照不可变。

## 关联文档与发布门槛

实际银行文件导入、分配及余额完整性见`FINANCE-BANK-CONTROL-API.md`；计提、采购、关账、差错、档案和模型分别见同目录对应文档。第三方模型/OCR/税务服务未配置时必须明确待配置，不把接口、人工确认或本地解析称为实际接通。金蝶替代还需真实导出映射和并行对账确认。

本轮为新增V91–V112及相关旧业务桥接。V111辅助维度沿真实业务身份冻结，手工分录只提交已授权候选的编号；科目必填维度仍须独立发布。后补的独立库存/耗用价差分类使用不可变补充记录，不覆盖原来源快照或已成凭证；原价差保留真实金额，不因缺分类改成零。

发布必须同一提交CI制品、全量回归、数据库和原件备份/恢复演练、迁移检查、健康及线上页面验收；本地构建成功不豁免CI制品门禁。
