# 财务报销一期：设计锁定与验证

## 已确认范围

功能和视觉均已确认。审批流程补充确认：门店负责人 → 财务 → 集团领导，三人由后台逐店配置且各有独立审核记录。最终审批完成才生成费用事实与凭证草稿；付款不等于审批、审批不等于正式记账。禁止自审，不代填真实审批人。

## 视觉规范

参考工作区 outputs/finance-concepts-20260921-v1 中的三张已确认图片。背景 #F3F7FA、白色面板、深蓝文字 #153E54、主按钮 #2378ED、成功青绿、异常琥珀、重复拦截红色；圆角 10–12px，细描边。使用现有品牌标识与外壳，不重做其他中心。

手机端按身份、报销内容、凭证、保存状态、操作顺序排列，控件不小于 44px，正文 15–16px。桌面审核为单据队列、凭证对照、审核操作三栏；台账为汇总带、门店表格和分类横条，不改成卡片网格。使用现有无衬线中文字体；标题 24–28px，分区 18–20px，控件 14–16px。图标采用 20px、1.8px 线条的单色图标，含文档、上传、云端、离线、警示、勾选、放大和箭头。

复用现有导航与品牌；概念图的示例数据不进入生产。现有绩效等模块全部保留。审批中需要的阶段提示、发票号码确认、多发票、配置页、申请列表及付款登记是完成业务必需的延伸，使用同一设计体系。无新增摄影或营销图片，凭证预览来自真实已授权附件。

## 数据与安全

- 金额使用十进制定点数；请求修订号防止旧页面覆盖新数据。
- 发票号规范化并保留前导零；数字发票使用完整号码，传统票使用代码和号码组合。租户集团内唯一；发票文件哈希作为额外重复线索，不能替代票号。
- 发票占用在提交事务内完成；退回允许修订但占用保留至重新提交或撤回；拒绝/撤回释放占用。审批完成不可覆盖。
- 身份、门店、公司、审批链均以服务端事实为准；草稿公司配置变更提示重新核对；历史快照不随员工转岗或公司改名变化。
- 原始附件独立存储并保留哈希、扫描结果和审计，不使用工作照片自动清理表。照片不强制裁剪旋转，保留票据原件。
- 每次审核冻结当时的金额、发票明细及原件索引。退回后移除附件只将其退出当前草稿，历史审核仍可在权限校验后下载当时原件；原件元数据禁止覆盖或删除。
- 离线缓存按租户/账号/任职隔离，使用本机不可导出密钥加密；不缓存认证令牌。空间不足明确报错；不会把本机保存显示成云端已保存。
- 所有财务表启用并强制 RLS；所有 API 仍检查操作权限及门店/单据范围。数据库唯一约束在并发提交时仍生效。

## 实施状态

开发分支：`feat/finance-reimbursements-20260921`，最初基于 `a11e43526d5923419dfa052ae9a13eb72544e76f`，发布前合入已上线的 `053d270` 主线。财务申请、三段审核、费用台账、门店配置及权限入口已接入现有应用。为保留主线 V69–V71，财务迁移调整为 V72，仅新增财务数据结构，不转换现有经营成本数据。

实际边界：

- 电子 PDF 提取明确标注的发票号码、代码及金额候选值，必须人工确认；图片 / 扫描件的 OCR 服务尚未接入，不声称已经自动识别或税务验真。
- 类别建议来自门店关键词和已审批历史，不调用 AI 模型，不自动决定会计科目或税额。
- 终审产生分类金额记录与借贷平衡的凭证草稿；不是正式记账、税务发票或完整财务报表。付款登记不会调用银行接口，首期只支持足额登记。
- 费用台账仅统计报销中的当期费用；库存、资产、预付及已记成本单列，不与既有库存耗用重复合计。未来完整报表仍需采购、库存、收入、税务、总账和结账能力。
- 离线仅支持已经打开的草稿，不包含首次离线进入应用、离线审核、离线付款或后台自动提交。恢复范围为同一浏览器、租户、账号、任职，保留 7 天恢复资格；过期草稿在读取时清理，不承诺浏览器未启动时执行物理清理。加密不替代可信设备、账号及浏览器安全。
- 未接入金蝶 API，历史去重清单需导入已有已报销票号；未导入的旧系统票据无法凭空参与查重。

## 上线前配置

1. 每店 / 总部确认真实法人公司、税号、三个不同的实际审核账号及科目；审核人另需已发布的 `finance.review`、`ui.module.finance` 和相应门店数据范围，不因被选为审核人自动扩权。
2. 给申请、审核、只读和付款岗位分别授予所需权限；`finance.configure` 为管理权限，不向普通岗位自动发布。不得为了试点批量给所有人财务读取权限。
3. 核验生产扫描服务可扫描原始 PDF / 图片；财务凭证不采用重新编码图片替代扫描。将 `FINANCE_ATTACHMENTS_ROOT` 配置到持久化磁盘并纳入原件及数据库配套备份，默认使用现有附件持久化根目录的 `finance-originals` 子目录。
4. 清理并导入金蝶历史已报销票号，先使用测试门店完成真实审批账号、原件上传、退回、查重和付款登记验收。未连接银行，不会真实付款。
5. 确认图片 OCR 供应商、费用与数据授权后另行接入；完成隔离浏览器和企业微信真机验证，再申请合并 / 推送 / 部署授权。

技术依据：[PostgreSQL 约束](https://www.postgresql.org/docs/current/ddl-constraints.html)、[PDFBox 3 加载接口](https://pdfbox.apache.org/3.0/migration.html)、[Web Crypto 加密接口](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt)。
