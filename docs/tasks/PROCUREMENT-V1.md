## 必须保持的业务规则

- 低库存生成待店长审核采购单，店长可追加物品；主动需求提交后直接推送采购负责人。
- 所有数量使用后台物品规格与单位换算，采购价格和换算保留快照。
- 收货记录提交不增加库存；配置的主管复核通过后才入库，复核及库存更新在同一事务。
- 分批收货、部分入库不结束有差异的采购单。各行采购数量和累计审核入库数量全部一致才可结单。
- 首次收货差异满30天仍未闭环，推送门店财务负责人、财务总监、副总经理和总经理；补传、退回、部分入库不重置时间。
- 两种采购入口共用后续流程；工作台待办和门店库存页提供入口，不新增独立主菜单。
- 门店配置责任人、收货人及四类预警人员，缺配置不能假装已发送。
- 并发和网络重试不得重复入库；历史事件和库存流水不可覆盖。

## 实现边界

- 入口：角色工作台的“采购与收货”子功能和采购待办；门店库存页也提供入口。
- 采购物品来自本门店已启用配置。新物品需先建档；Excel 导入仅预览、添加草稿，不直接入库。
- 到货数量 = 合格数量 + 拒收数量。累计合格量（含待复核批次）不能超过采购数量；未到货可分批登记。
- 收货使用基础库存单位；采购允许后台配置的基础或采购单位，换算系数与价格存为本单快照。
- 复核锁定采购单及库存行，保存实际入库前后数量；拆分入库尾差按累计金额处理。
- 仅草稿原填写人可以填写原因，撤销从未提交的误建收货草稿。照片、数量和操作历史保留；已提交、退回补充、已复核记录不能借此撤销。
- 满30天以第一次提交收货、确认尚未复核入库的时间为起点。部分入库、退回、重提交不重置。按订单及接收角色去重，调整接收人后新责任人可以收到预警。
- 采购入库增加库存数量和存货价值，不重复生成耗用经营成本；后续使用既有消耗审核及成本流水。
- 通知区区分站内通知、未绑定企微、待发送、发送失败、已发送及接收账号停用；不把站内生成冒充企微送达。

## 上线配置与验收

1. 备份、隔离还原和数据库迁移验证通过后，才允许执行 V78；新增采购表与现有库存流水一起备份。保留主线已经发布的 V74-V77，不得回写既有迁移文件。
2. 管理员配置每个门店的店长、采购经办人、复核人、收货人及四类预警接收人。配置责任人本身不会授予权限。
3. 在岗位功能方案中发布 `procurement.read`（门店业务查看及按责任办理）和按需 `procurement.request`（发起并查看本人需求）；同时配置正确的门店数据范围和工作台入口。`procurement.configure` 不可下放普通岗位。
4. 管理员启用门店采购，并为需要自动补货的物品保存最低库存及高于最低值的补足目标。
5. 环境启用 `PROCUREMENT_SCHEDULER_ENABLED=true`、明确 `PROCUREMENT_TENANT_IDS`；默认每60秒检查，未配置租户时拒绝启动，不扫描所有租户。
6. 企微沿用已有 OAuth、个人绑定和通知投递配置；采购消息不推送到群聊。上线检查实际送达和订单链接。
7. 附件位于 `ATTACHMENT_STORAGE_ROOT/procurement`，纳入现有附件根目录备份；文档上传需有效安全扫描配置。采购证据不属于日清照片5天清理范围，本版未增加采购附件自动删除任务，不能声称已实现结单后的自动清理。
