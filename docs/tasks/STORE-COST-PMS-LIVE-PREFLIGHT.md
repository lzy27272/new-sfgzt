## 本轮本地修复

`tools/uat/monthly-pms-kpi-collector.mjs` 原先在写入时只保留全部门店最近120条记录，门店增加或同月重采会挤掉历史，不满足三年保留要求。

新增 `tools/uat/pms-summary-store.mjs` 并接入该月度采集器：

- 取消按总条数裁掉历史，不自动按采集日期删除旧月份。保留已有记录和新修订，不改变原业务验证标识或正式KPI资格。
- 每条脱敏汇总按内容哈希独立存入相邻 `.history/YYYY-MM/` 目录；首次写入也先留存已有历史，再原子替换当前发布文件。旧归档不能被同名覆盖。
- 独占锁覆盖读取、合并、归档和发布，防止并发写入互相覆盖；完全相同的记录重试不会增加重复条目。相同编号不同内容、同店同期间同采集时间的歧义版本明确拒绝。
- 旧文件损坏、重复JSON键、历史冲突、归档校验失败或容量超限时，明确失败并保留旧发布文件，不初始化为空、不自动删记录腾空间。
- 活跃发布包上限64MiB/10万条；超限必须安排分片或归档读取改造，不能恢复为截断最近N条。
- 纯报表计算和留存测试不再在模块加载时依赖浏览器；只有真实采集函数调用时才加载原浏览器依赖。本轮没有运行该真实采集函数。

这是**本地月度采集保存模块**的修复，未修改云端正在运行的独立小时/日归档模块，也未证明两家罗盘PMS试点的发布流程已调用本模块。后续接入方必须核对实际执行脚本与发布目录，不能只上传主站Web包就认为该修复已上线。

### 操作与恢复边界

- 文件归档不是异地备份，须纳入已验证的备份范围并执行还原演练；图片5天清理任务不得包含这些数值汇总与版本目录。
- 当前不提供自动删除历史的任务；三年是最低保留目标，不因本模块的大小保护删除三年以内或更早的数据。
- `PMS_SUMMARY_STORE_BUSY` 表示已有写入锁。确认活动写入完成后可重试；若进程崩溃留下锁，须先核对进程、日志及文件完整性，再由运维处理。不会按锁文件年龄直接抢占。
- 归档写完后、发布前如果进程失败，可能留有尚未发布的采集版本。归档不等于已发布，更不等于经过正式KPI确认；恢复前必须核对发布记录与来源，不自动重放全部归档。
- 回退应用代码前应暂停旧月度采集器，保留新的发布文件及 `.history`；旧代码的120条截断逻辑不能再次运行。不得通过回滚代码覆盖这些历史文件。
