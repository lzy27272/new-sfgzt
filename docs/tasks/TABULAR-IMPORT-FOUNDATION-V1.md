# 中台统一表格导入基线 V1

## 目标

所有适合批量录入的中台数据统一采用“下载标准模板 → 上传安全检查 → 整表校验与预览 → 人工确认 → 原子写入 → 结果与审计留痕”的流程。Excel 只是批量录入载体，不能绕过原有权限、组织范围、审批、发布和状态机。

首个生产适配器为 `STORE_RESOURCE_INITIALIZATION`，用于新门店一次性导入物品主档、期初库存和固定资产。期初库存不直接修改余额，而是同时生成不可变的 `OPENING + IMPORT` 库存流水。

## 统一约束

- 首期仅接受无宏 `.xlsx`；拒绝公式、宏、外部链接、非法压缩路径和超出解压预算的文件。
- 上传文件先经过附件恶意代码扫描；正式环境扫描器缺失、不可用或超时均拒绝导入。
- 用户只填写组织编码、员工工号、岗位编码、物品编码等业务键，不填写数据库 UUID。
- 上传和预检不写正式业务表；任意一行不合法时整批不能应用。
- 应用使用事务和行锁；重复点击或重复上传同一文件不会重复创建业务事实。
- 默认仅新增，不静默覆盖已存在的数据。库存、经营事实和 KPI 事实只能追加或冲销，不能通过导入覆盖历史。
- 保留文件哈希、模板版本、操作者、目标组织、逐行错误、结果资源映射和审计事件；不在数据库保存原始工作簿二进制。
- AI 可辅助识别列和解释错误，但最终字段映射与入库规则必须经过确定性校验。

## 适配器分期

| 阶段 | 数据 | 导入结果 |
| --- | --- | --- |
| 已实现 | 门店物品、期初库存、固定资产 | 校验通过后一次性正式入账 |
| P0 | 门店/部门基础资料、员工资料、员工任职和负责门店 | 创建待激活资料；员工密码不进入表格 |
| P1 | 岗位、工作包、工作事项、提醒、证据链、日报模板、标准、企业规则、KPI 模板 | 只生成草稿，仍须在原模块审核和发布 |
| P1 | 物品规格、采购/领用单位换算、标准用量、布草洗涤价格 | 生成门店配置草稿，经授权人员确认后生效 |
| P2 | 库存收货/领用/消耗/退回/报损/盘点、批量任务、PMS/OTA/KPI 历史事实 | 生成待复核或待过账批次，复核后追加业务事实 |

每个后续适配器复用相同的导入任务、模板下载、扫描、预览、错误表、应用锁、历史记录和审计能力，不再自行实现一套上传逻辑。

## 禁止通过表格直接执行

- 审批、驳回、复核、签收、确认、申诉处理和结算锁定；
- 发布、启用、停用、删除、恢复和归档；
- 任务完成、验收、日报提交和其他状态流转；
- 资产库存移交中的异议、盘点确认及三方确认；
- 企业微信入职审批、绑定和解绑；
- 密码、OAuth 凭证、Token、Cookie、Webhook 密钥及其他秘密；
- 现场照片、证据文件、AI 建议和系统计算结果。

这些动作必须由实际责任人在原业务流程中完成，确保权限、人员意志和审计链真实有效。

## 新店库存与资产模板 V1

### 物品与期初库存

物品编码、物品名称、分类、计量单位、单位成本、最低库存、期初数量。门店内物品编码防重；期初数量为零时只创建物品主档和零余额。

### 固定资产

资产编号、资产名称、资产分类、规格型号、序列号、计量单位、原值、购置日期、存放位置、责任人工号、责任人岗位编码、状态。责任人必须解析为该门店组织范围内的有效任职。

### 应用结果

- 物品、库存余额和固定资产在同一事务创建；
- 大于零的期初数量生成一条不可变期初流水；
- 每一行与创建的物品、资产或库存流水建立不可变结果关联；
- 数据在预检后发生冲突或责任人任职失效时，应用被拒绝并要求重新预检。
