# 副总登录恢复与正式门店分管验证

## 问题与修复边界

视频中的失效企微入口在点击“返回中台登录”后仍进入身份加载页。旧的企微会话提示和自动授权逻辑没有让出账号密码入口。

- 返回、登录状态失效、主动退出均进入明确的 `#/login` 页面，并清除旧会话提示。
- 身份读取和一次性凭证交换期间也可以选择账号密码登录；迟到的结果不能把已取消的页面重新打开。
- 手动登录选择仅是页面偏好，不是凭据；浏览器存储不可用时仍可通过地址恢复。密码和令牌不写入本地存储。
- 账号登录增加超时；新登录等待已有退出请求结束，避免迟到的退出响应清掉新会话。
- 正常企微授权、有效一次性凭证仍保留免密入口。失败后重试企微授权需要明确点击。

## 数据范围

按用户授权，当前副总任职使用后台已有的“指定分管门店”配置，指定归来、解放路 MOOODSHIFT 酒店，排除测试门店和作为组织使用的“集团总部”。保留总部任职、上级关系和原有 46 项功能权限。未来新增门店或调整分工通过员工编辑配置，不动态把测试门店或新任职纳入。

指定门店不应使本人总部工作记录不可读。工作详情、附件和草稿操作增加“当前有效任职拥有该记录”的逐条检查；所有操作仍要求各自权限，复核仍要求组织范围。不授予总部所有员工记录权限，也不自动授予填写权限。

一次性范围配置采用短事务和精确版本前置检查：管理员若同时改过方案、任职或门店列表，则停止而非覆盖。配置前保留加密备份，配置后的审计记录保存前态、门店与任职清单；不改密码、不迁移组织、不代做企微绑定。

## 本地验证

- 前端 221 项自动测试通过，Pilot 构建通过。
- 用户批准使用本机隔离浏览器；内置浏览器缺少运行组件，故使用本机 Chrome + Playwright，只拦截本地模拟接口，不使用真实员工凭据。
- 8 个交互场景通过：失效入口返回手动登录、刷新、密码错误后重试、旧企微提示、存储禁用、身份读取挂起、交换挂起及迟到结果、401 恢复、正常企微跳转和有效交换。其中相关组合计为同一场景。
- 总部分管集成测试验证：两家门店可见、测试门店不可见、上级仍可见总部员工、督办去重、本人记录访问、不同任职/其他员工拒绝访问、缺少操作权限仍拒绝访问。
- Core API 完整构建通过：368 项测试，0 失败、0 错误、3 跳过；OTA 全模块回归通过。发布记录另存实际日志。
- 配置 SQL 已在生产备份的隔离还原库执行成功，验证 6 条任职门店关联和 1 条审计记录；隔离库与明文临时备份已清理，加密备份保留。
