本次按已确认的功能方案和五张效果图实施。以下为初次本地开发验收记录，当时未合并主线、未推送 GitHub、未部署云端，也未修改线上数据；后续主线集成复验见文末。

## 已实现

- 人员与任职先选择门店或总部，再进入人员列表；同一员工在一个门店只显示一行，多任职可展开。支持搜索、部门、岗位、历史任职筛选。管理范围不当作员工任职归属。
- 当前人数按启用员工、启用账号和有效任职计算；未来、到期、已结束任职不增加当前在职人数。结束单项任职和停用全部岗位是两个不同入口。
- 工作台同时呈现团队和个人看板，四个状态卡可进入明细；团队包括授权范围内本人及下属，个人只统计当前任职，不与团队数字相加。
- 工作台、我的工作和团队工作共用日、周、自定义及本月累计筛选；下钻、详情关闭和返回保留日期与门店条件。
- 总数与分组由服务端按完整授权范围计算，先汇总再分页；不再将当前页条数当作整体总数。
- 审核队列跨工作日期展示；最近提交按近七天实际提交时间显示，保留历史补交入口。非日清未完成工作进入单独的跨期未结队列。
- 多条提交记录可在详情切换，每条分别读取内容、附件及审核状态；重复记录优先打开待审核记录，选择记录仍必须属于当前工作并通过服务端原有权限检查。
- 桌面并列展示看板；手机采用纵向卡片、团队/个人快捷定位、双列状态入口及移动端列表布局。

## 统计口径

| 项目 | 口径 |
| --- | --- |
| 待提交、逾期未提交、待审核、已完成 | 互斥的四个工作状态；已提交待审核不计为闭环完成 |
| 已补交 | 有效提交晚于截止时间的附加标记，不是可叠加的第五种工作状态 |
| 闭环完成率 | 已完成必做工作 / 应完成必做工作 |
| 提交率 | 已提交待审核及已完成必做工作 / 应完成必做工作 |
| 按时提交率 | 截止前已有有效提交的必做工作 / 应完成必做工作；不因等待主管审核而降低 |
| 当日与截至当日月完成率 | 使用服务端营业日及对应月份，按工作归属日期计算 |
| 重复服务、客诉、非必填记录 | 单独显示记录条数与工作项数，不纳入必做完成率分母 |
| 无应完成工作 | 显示“—”，不显示虚假的 100% |

历史日清漏交仅在对应工作日期查询中出现，不滚入今天的逾期数字。未来日期不计入完成率分母。新查询是只读接口，不调用旧的 KPI 快照写入流程，不回写已结算 KPI。原有数据保留和附件清理政策不变。
