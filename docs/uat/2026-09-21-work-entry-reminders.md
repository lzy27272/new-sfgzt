# 工作填报与岗位督办修复验证

本轮按用户“跳过效果图，直接修改代码”的指令实施；在独立分支 `codex/work-entry-reminder-fix` 完成开发，基线 `c901f67`。开发验收时未修改生产人员绑定与工作数据。用户后续已授权合并、推送、部署；发布结果以同批发布目录中的云端验收记录为准，不将本地测试等同于线上验收。

## 调整内容

| 范围 | 新行为 |
| --- | --- |
| 工作清单和各周期报告 | 不再填写通用“是否有异常”“工作结果/完成情况”；保留工作专属事实、数量、照片与证据规则。历史已提交内容保留。 |
| 客房服务员 | 领用只显示领用相关字段，工作车整理只显示整理证据和选填说明，耗品布草归位保留使用数据，日报保留做房数量和台账。 |
| 对客服务、客诉、遗留物 | 发生时登记，可以连续形成独立记录；未发生不催交、不逾期、不计必做工作完成率分母。日报汇总全部记录。客诉填写房号。 |
| 遗留物移交 | 登记房号、物品、数量、时间、位置及同店接收人，不再填写“是否发现遗留物”；发生后仍按原证据及复核规则提交。没有新增接收人电子签收流程。 |
| 店长向前厅主管派单 | 可按姓名、岗位、部门搜索和刷新当前授权门店的人员；不扩大人员可见范围。 |
| 前厅主管工作缺失 | 明确有效的前厅主管任职不再被“店助兼管前厅”配置阻断；补齐缺失的工作包和日报规则。历史漏配从下一日开始，不倒灌此前漏交；新任职保留原生效日生成行为。 |
| 副总企微督办 | 显示企微未绑定、排队、发送结果；过滤已结束及历史日清催办，保留有效的当日督办。企微“已发送”不等于本人已阅读。 |

取消通用问题不等于取消真实问题管理：已有巡检问题说明仍保留，原来依据“是否有异常”触发的条件证据改为根据实际问题说明判定；业务专属开关（例如预抵特殊需求）不受影响。

## 已定位的生产现象

- 副总账号已有站内督办消息，但没有有效的个人企微绑定；其他已绑定用户存在成功投递。此轮不猜测、代绑企微身份，发布后需要本人完成验证绑定，再做真实收信验收。
- 解放路酒店的前厅主管任职、账号、组织均有效，但门店仍配置为无前厅主管模式，导致其工作包漏配。
- 后端授权人员查询可返回前厅主管；没有复现后端拒绝该人的权限故障。本次改善前端人员查找与刷新，真实账号仍需发布后回归。

## 升级与数据保护

- 新增 V71，复制并发布新版工作项和表单，不改写旧发布版本。
- 当前未提交草稿改用新表单；保留草稿原始业务内容和附件。
- 当前发生型工作允许继续新增记录；已经提交的记录不被覆写。
- 工作版本更新后，旧日报模板通过同一工作包定义及条目编码识别新记录；继续检查租户、员工、日期和组织范围。
- 已提交的工作、历史工作期望、原始附件、旧模板和日报模板的前后快照一致性，已在真实 PostgreSQL 升级测试中验证。
- 不删除或追改历史 KPI 结算。没有修改图片留存策略。

## 自动验证

- 前端：310 项测试通过，TypeScript 检查和生产构建通过。
- 后端针对性回归：52 项，覆盖工作生成、重复登记、日报汇总、完成率分母、权限范围、升级保留历史、督办队列。不是全仓全部测试或所有真实岗位的逐页验收。
- V70 → V71 升级用独立 PostgreSQL 和无 RLS 绕过权限的连接验证；测试结束后由测试框架关闭隔离数据库。
- 浏览器：实际组件在桌面 1440×1000、手机 390×844 上验证；客诉连续两次提交、遗留物必填校验和同店人员选择、前厅主管搜索/刷新/下达均通过，无页面脚本错误。接口采用测试拦截，不冒充生产端到端测试。
- Browser 插件运行组件缺失；沿用用户许可使用本地 Playwright 验证。
- 浏览器脚本：`tools/uat/verify-work-entry-ui.mjs`；截图位于工作区外的 `work-entry-reminder-fix` 验收证据目录，不进入生产包。

## 发布后必须复核

1. 前后端同批发布，数据库升级前备份；检查迁移记录和服务健康状态。
2. 新表单无通用重复问题；照片规则仍有效；同日对客服务/客诉/遗留物多次提交能进入日报并独立复核。
3. 使用真实店长账号搜索前厅主管并下达测试任务，确认主管能接收。
4. 确认漏配前厅主管的下一日工作和日报已配置，且没有生成之前几天的漏交处罚。
5. 副总本人完成企微绑定，验证店长当日逾期督办可收到、点击可进入正确门店，不补发无效历史催办。

本轮没有实际发送企微消息，也没有进行手机真机拍摄上传验证；这些不在本地测试通过的结论中。
