# 客房日报合并、遗留物保管与库存使用范围模板

## 本次范围

基线：`336ed2e77dcd003d17944e6a52967105fc68c766`。开发分支：`feat/housekeeping-daily-custody-20260924`。

本记录覆盖开发及 2026-09-25 本地隔离验收。验收未操作真实员工、日报、库存或企微消息。用户随后已明确授权合并、推送及部署；实际发布结果以对应部署凭据为准。

### 库存与固定资产 Excel

- 标准模板升级为 V4，物品、固定资产均包含“使用部门”“适用岗位”，附部门和岗位参考表。
- 使用部门可填写多个名称/编码或明确填写“全店通用”；适用岗位支持多个名称/编码及“不限岗位”。
- 新模板不接受空白使用范围；旧版无范围列的导入仍保留“未配置”状态，不擅自扩大领用范围。
- 增加“仅更新使用范围”：模板预填本店现有编码，预检和确认时校验当前版本，只更新部门、岗位及范围版本。
- 使用范围更新不修改数量、单价、库存金额、流水、成本或固定资产保管人；重复确认不会重复执行。

### 客房日报

- 服务案例、遗留物品并入同一客房日报，沿用当地营业日 15:30 开放和现有日报提醒规则。
- 开放提醒统一为“今日日报与遗留物待填报”；不额外生成独立的服务案例、遗留物日清任务及提醒。
- 服务案例支持多条、房号/区域、文字、照片；没有案例可不填。
- 遗留物显式选择“有/无”；有物品时填写名称、数量、房号/区域、发现位置与时间、照片和本店接收人。
- 照片可从相册选择，不强制实时拍照；待上传文件及上传回执按租户、账号、任职、记录隔离暂存。
- 保存草稿不发审核通知；日报提交、遗留物记录及通知在同一事务中提交，失败整笔回滚。
- 退回后通过原日报发起修订。原耗品数量未变时只引用已提交的耗用记录，不重复提交、扣库；修改已提交耗用仍需走原审核更正流程。
- 投诉事件不属于本次合并范围。

### 遗留物保管

- 工作台下增加“遗留物品保管”，支持清单、筛选、照片、审核及流转历史。
- 接收人限本店在职、有入口和接收审核权限的其他员工，不允许自行接收或跨店指定。
- 随日报提交后生成接收审核通知，企微仅向有效绑定成员发送，不发群消息。退回、重新指定或重新送审后不发送旧轮次提醒。
- 审核无误后进入独立保管清单；退回必须填写原因，保留全部历史。
- 前台凭出库权限核验领取人及物品、上传交接凭证后出库，支持分次领取。
- 接收和领取均校验版本、幂等键和门店权限，阻止重复入库、重复扣减、超额领取。
- 该保管清单独立于酒店物资库存及成本账，不自动形成酒店成本。
- 企微深链保持现有安全登录流程；指定接收人有多个任职时，只能切换到本人被指定、且仍有权限的任职。
- 手机上打开审核链接时，物品详情排在清单前面。

## 数据库升级与权限

- V80：新增固定资产使用部门、岗位范围表；原资产默认为 LEGACY，不改变账面事实。
- V81：新增日报照片、遗留物记录及不可修改的流转历史，启用租户隔离和关联外键。
- V81 仅取消当日/未来、尚无任何工作记录的两类合并任务占位记录，并写审计；不清理历史、草稿或已提交记录。
- 平台管理员及集团标准前台岗位获得新权限；发布新标准版本但保留管理员未发布草稿。门店自定义岗位方案不会自动扩大权限。

后台配置权限：

| 使用场景 | 权限 |
| --- | --- |
| 显示入口 | `ui.module.lost-properties` |
| 查看授权门店清单 | `lost-property.read` |
| 审核本人被指定的遗留物 | `lost-property.receive` |
| 办理客人领取 | `lost-property.release` |

接收候选人必须同时有入口和接收权限。实际企微推送还要求账号已有有效企微绑定及消息服务正常启用，本次没有代做绑定或发送生产消息。

照片沿用现有扫描、文件大小限制和图片留存策略。本次不会改变留存天数；若业务需要延长未领取物品证据的保管期，应另行明确保留规则后配置。

## 发布后验收建议

1. 下载 V4 标准模板和“仅更新使用范围”模板，核对物品、资产、参考页。
2. 使用本地模拟客房账号填写多条服务/遗留物，验证相册上传、中断恢复和日报统一提交。
3. 使用本地模拟前台接收人完成“退回 → 日报修订 → 接收入库 → 部分领取 → 全部领取”。
4. 检查手机窄屏和电脑宽屏，确认无内容截断、错误静默或照片丢失。
5. 上线前复核接收岗位、企微绑定、照片留存策略及数据库备份；真实员工提交、收发物品及企微通知由业务人员验收，不代做真实业务记录。
