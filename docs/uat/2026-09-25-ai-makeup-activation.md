# 妆容检查与启用状态修复验收

## 范围与边界

用户完成方案、电脑/手机效果图确认后要求修改并发布。此次只开放可配置的 MAKEUP 项，修正规则草稿/启用交互；不增加自动审批、正式退回、扣分或历史照片扫描。门店范围、每日配额、原提交人权限、原图留存策略不变。

旧三项规则可继续使用，读取时补充一个关闭且规范为空的妆容选项，不擅自替用户启用或填入制度。妆容适用标准、合理例外仍由管理员确认；不推断性别、身份、外貌吸引力或服务态度。

## 核验

- 前端模型测试覆盖新旧配置兼容、明确规范校验、草稿与生效版本分离、启用后旧版停用但不覆盖历史。
- 后端覆盖四项规则保存/启用/读取、50 个以上草稿时仍返回旧生效版、模型未给清晰度或图片不可辨认时转 UNKNOWN、多人/错误证据不能当作通过。
- 既有权限、租户/试点门店隔离、照片所属人、补拍/申诉/复核、重试配额、过期图片和 worker 恢复测试继续通过。
- 浏览器使用真实 React 页面和本地模拟接口；内置 Browser 因缺失 browser-service.mjs 启动失败，使用用户此前批准的本地 Playwright 回退。
- 12 个交互场景：旧草稿、妆容勾选/规范/例外、预览、保存草稿、保存并启用、刷新回读、保留旧启用版本、409 冲突、读取失败、异常保存响应、岗位切换、样例上传/查看/移除、手机展开范围/填写/提交等组合场景。
- 320、390、443、768、1036、1586 像素宽度无横向溢出；未产生页面异常；测试没有向外部模型发送员工照片。

## 不可替代的业务验收

上述通过证明保存、启用、边界保护与展示流程，不代表真实照片识别准确率已验收。需要管理员按真实制度配置妆容规范，由原提交人选择分人清晰近照，再由主管核对建议。没有在本次发布中擅自修改真实门店规则或检查今天早上的员工照片。
